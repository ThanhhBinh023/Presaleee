## Defects and behaviour findings recorded by this run

| # | Area | Finding |
| --- | --- | --- |
| F1 | G11-13 / code | `knowledgeRoutes.ts` and `ragRoutes.ts` apply `requireAuth` + `requireOrganization` only, so a VIEWER can ingest, delete and query the whole knowledge vault. Every other write surface in the API is role-checked. |
| F2 | G11-01 / G11-09 | `IngestDocumentUseCase` passes the raw `content` to `createDocument`, but `knowledge_docs` has no content column and the repository INSERT ignores the field — the original text only survives as sliding-window chunks, so a document can never be shown or re-exported verbatim. |
| F3 | G12-01 | `hybrid_search_chunks` selects id, doc_id, chunk_content, metadata and the ranks but not `chunk_index`, and `PostgresKnowledgeRepository.searchHybrid` then defaults it to 0 — every returned chunk reports window 0, so a UI cannot highlight or de-duplicate matches inside a long document. |
| F4 | G12-07 | Ingesting identical text twice creates two documents and two sets of 768-dimensional vectors: there is no content hash or unique constraint, so a re-upload silently doubles recall noise and storage. |
| F5 | G11-04 | The GENERAL fallback for category/domain fires only for an omitted or null value; an empty string is a 400 "category is required." A form that clears the field and submits "" therefore fails where omitting it succeeds. |
| F6 | G12-04 / code | The domain filter is applied to both the semantic and the lexical branch of `hybrid_search_chunks`, so a filtered query can return fewer than topK chunks with no signal that the corpus was narrower than requested. |
| F7 | G11-15 / G12-11 | The answer and overview success paths are only covered as guards plus the sanitized 502: the FastAPI LLM service on http://localhost:8000 is offline, and the RRF fusion itself is asserted through ranking rather than through generated prose. |
| F8 | G12-09 | The ingest rollback (embedding failure deletes the document row) cannot be exercised against the live Gemini provider, so only its post-condition invariant is proven — no chunk-less document exists. |
